New skill · implementation review

Briefing

When you ask an agent for a summary, an engineering explanation or a decision, it can now use the same briefing pattern in HTML or Markdown. The new skill keeps the explanation in front of you, gives evidence its own linked notes, and keeps your comments attached to the passage you were reading.

Ready to use

Invoke briefing by name. The current briefing skills remain available under their existing names.

01 Choose the Brief

The agent chooses the purpose separately from the medium, using the reader and reading budget you give it. It can infer those choices from the task; a different kind of brief is valid when its job is clear.

Try the same engineering explanation as HTML or Markdown.

02 Follow the Evidence

A short explanation still needs support. The skill defaults to a deep chain of evidence, with tests and source for code claims. You can ask for a shallower chain while the brief itself stays concise.

03 Return a Comment

After reading, you can question a specific heading, figure or passage. The returned map identifies that target and the document version. HTML keeps the existing notes format; Markdown has a saved adjacent map for readers without inline comments.

The Markdown map example is editable text. Inline Markdown controls depend on the reader. In a standalone browser, HTML edits persist in browser storage; saving into the original file requires the host's supported write path.

04 What Was Checked

The checks exercise the reader's loop as well as the stored data. They found and caught a browser serialization detail that initially made an unchanged saved page look like a new revision.
